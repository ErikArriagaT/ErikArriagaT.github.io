Actividad 08

"File Path Traversal: Bypass con Rutas Absolutas"

↓ Descargar Reporte (PDF)

Objetivos de la Práctica

  • Comprender la vulnerabilidad de Directory / File Path Traversal y cómo permite a un atacante leer archivos arbitrarios en el servidor.
  • Identificar y evadir mecanismos de defensa deficientes, específicamente el bloqueo de secuencias de recorrido relativo (como ../).
  • Explotar la vulnerabilidad utilizando una ruta absoluta para acceder a archivos sensibles del sistema (ej. /etc/passwd).

Introducción

La vulnerabilidad de Path Traversal (o salto de directorio) ocurre cuando una aplicación web utiliza la entrada del usuario para construir una ruta de archivo y no la valida correctamente. Esto permite a un atacante manipular la ruta para acceder a archivos fuera del directorio raíz de la web, exponiendo credenciales, código fuente o archivos del sistema operativo.

A menudo, los desarrolladores intentan mitigar esto bloqueando o eliminando secuencias de caracteres típicas como ../ (utilizadas para subir un nivel en el directorio). Sin embargo, este enfoque de "lista negra" es ineficaz si la aplicación procesa directamente la ruta del archivo ingresada. Si en lugar de usar una ruta relativa se envía una ruta absoluta (desde la raíz del sistema operativo), el filtro no detecta los puntos y la solicitud maliciosa tiene éxito.

Desarrollo

La resolución de este laboratorio se llevó a cabo interceptando y modificando las peticiones HTTP entre el navegador y el servidor:

  1. Identificación del Vector: Al navegar por la aplicación web, se detectó que las imágenes de los productos se cargaban mediante una solicitud al endpoint de imágenes usando el parámetro filename (por ejemplo: /image?filename=15.jpg).
  2. Prueba de Vulnerabilidad Básica: Se interceptó la petición y se intentó un ataque estándar de recorrido de directorios modificando el parámetro a filename=../../../etc/passwd.
  3. Análisis de la Defensa: El servidor devolvió un error o no mostró la imagen, indicando que existía un mecanismo de defensa bloqueando explícitamente las secuencias ../.
  4. Bypass (Evasión): Para evadir el filtro, se omitieron las secuencias de salto relativo y se inyectó directamente la ruta absoluta del archivo objetivo. La petición se modificó a: filename=/etc/passwd.
  5. Explotación Exitosa: Al enviar la petición modificada, el servidor validó la ruta sin detectar los puntos bloqueados y devolvió en el cuerpo de la respuesta el contenido completo del archivo /etc/passwd, demostrando la vulnerabilidad crítica.

Conclusiones

Este laboratorio evidencia por qué las defensas basadas en listas negras (bloquear cadenas específicas como ../) son insuficientes y peligrosas en ciberseguridad. Los atacantes pueden encontrar múltiples formas de evadir estas restricciones, ya sea usando rutas absolutas, codificación URL o secuencias anidadas.

La mitigación correcta de un Path Traversal debe basarse en el principio de menor privilegio y una estricta validación de entrada. En lugar de bloquear caracteres malos, se debe usar una lista blanca de archivos permitidos o, como mínimo, validar que el nombre del archivo final (después de resolver la ruta) sea estrictamente el nombre base (basename) y no contenga directorios subyacentes antes de procesarlo en la API del sistema de archivos.
