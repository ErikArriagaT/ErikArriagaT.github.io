Laboratorio 02

"LAB 08: File Path Traversal (Absolute Path Bypass)"

↓ Descargar Reporte (PDF)

Descripción General

Explotación exitosa de una vulnerabilidad de File Path Traversal. Se logró evadir las restricciones de navegación relativa (../) inyectando directamente una ruta absoluta, obteniendo acceso a la raíz del servidor para la extracción de archivos críticos de configuración.

Objetivos de la Práctica

  • Demostrar la ineficacia de los filtros de seguridad basados exclusivamente en el bloqueo de secuencias de directorio relativo.
  • Utilizar rutas absolutas para forzar al servidor a resolver directorios desde la raíz del sistema operativo.
  • Extraer archivos críticos (como /etc/passwd) para evidenciar el impacto de una validación de entrada deficiente.

Desarrollo

El proceso de explotación se dividió en las siguientes fases:

  1. Intercepción del Tráfico: Se capturó la petición HTTP encargada de cargar recursos dinámicos en la aplicación (por ejemplo, la carga de una imagen mediante el parámetro filename).
  2. Detección de Filtros: Al intentar inyectar secuencias estándar de salto de directorio (../../../etc/passwd), el servidor bloqueó la solicitud o devolvió un error, evidenciando un filtro activo contra caracteres relativos.
  3. Bypass del Filtro: Se modificó el parámetro para eliminar las secuencias relativas y solicitar directamente la ruta absoluta del archivo objetivo (filename=/etc/passwd).
  4. Extracción de Datos: El servidor procesó la ruta absoluta sin aplicar bloqueos adicionales, permitiendo la visualización del contenido del archivo crítico directamente en la respuesta HTTP interceptada.

Conclusiones

Esta práctica comprueba que bloquear secuencias específicas (listas negras) no es una solución robusta contra los ataques de Path Traversal. Un atacante siempre buscará alternativas, como proporcionar la ruta absoluta desde el directorio raíz, para sortear estas defensas superficiales.

Para asegurar correctamente el manejo de archivos, la aplicación web debe validar que la entrada coincida exactamente con un formato esperado o, preferiblemente, implementar un mecanismo de referencias indirectas en lugar de pasar nombres de archivos directamente a la API del sistema operativo.
