Actividad 11

"Path Traversal: Bypass manteniendo el prefijo del directorio base"

↓ Descargar Reporte (PDF)

Descripción General

Explotación de un fallo lógico en el control de acceso a archivos. Se logró eludir la validación del directorio base manteniendo intacto el prefijo obligatorio (/var/www/images/) y concatenando secuencias de Path Traversal (../../../etc/passwd), lo que permitió la extracción de archivos críticos del servidor.

Objetivos de la Práctica

  • Identificar vulnerabilidades lógicas donde la validación de entrada se limita a comprobar el inicio de una cadena (prefijo).
  • Construir cargas útiles (payloads) que satisfagan las reglas de validación superficiales mientras explotan el sistema de archivos subyacente.
  • Extraer información sensible del sistema operativo para demostrar el impacto de una mala implementación del control de acceso.

Desarrollo

La explotación de este laboratorio se centró en engañar al mecanismo de validación de rutas del servidor:

  1. Mapeo de la aplicación: Se identificó una función de visualización de imágenes que recibía rutas de archivos a través de un parámetro.
  2. Detección del control de acceso: Al intentar inyectar payloads tradicionales (../../../etc/passwd) o rutas absolutas (/etc/passwd), la aplicación arrojó un error indicando que la ruta del archivo debía comenzar con el directorio base permitido: /var/www/images/.
  3. Análisis de la vulnerabilidad lógica: Se determinó que el desarrollador probablemente implementó una validación del tipo startsWith() en el código, verificando solo los primeros caracteres de la entrada y confiando ciegamente en el resto de la ruta.
  4. Elaboración del payload: Para superar el filtro, se incluyó el prefijo exacto requerido y se le concatenó la secuencia de salto de directorio necesaria para llegar a la raíz. El payload resultante fue: filename=/var/www/images/../../../etc/passwd.
  5. Ejecución y Extracción: El servidor validó exitosamente que la cadena comenzaba con la carpeta permitida. Posteriormente, al pasar esta cadena al sistema de archivos del sistema operativo (OS), este resolvió los saltos ../, retrocedió hasta el directorio raíz y devolvió el contenido de /etc/passwd.

Conclusiones

Esta práctica ilustra perfectamente los peligros de las validaciones "ingenuas". Verificar que una cadena comience con un valor seguro no garantiza que el destino final del archivo sea seguro, ya que los sistemas operativos resuelven las rutas relativas (../) independientemente del prefijo.

Para prevenir esta vulnerabilidad, los desarrolladores deben canonicalizar (normalizar) la ruta del archivo proporcionada por el usuario antes de realizar cualquier validación. Solo después de que se hayan resuelto todos los saltos de directorio (obteniendo la ruta absoluta real) se debe verificar si el archivo reside dentro del directorio base permitido.
