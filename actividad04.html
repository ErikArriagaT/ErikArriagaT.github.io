Actividad 04

"Una página demasiado convincente"

↓ Descargar Práctica (PDF)

Objetivos de la Práctica

  • Comprender el funcionamiento de los ataques de ingeniería social, específicamente el robo de credenciales mediante phishing.
  • Diseñar y desarrollar una página web ficticia en HTML estructurada para engañar al usuario.
  • Utilizar el framework Social-Engineer Toolkit (SET) para importar el sitio diseñado, alojarlo en un servidor local y capturar las credenciales.

Introducción

La ingeniería social se basa en la manipulación psicológica para engañar a los usuarios y lograr que revelen información confidencial. Uno de los métodos más efectivos es el phishing, donde un atacante falsifica la apariencia de un sitio web para interceptar datos sensibles.

Para esta práctica se utilizó The Social-Engineer Toolkit (SET), un framework de pruebas de penetración de código abierto diseñado específicamente para automatizar ataques de ingeniería social. A través de su módulo Credential Harvester, es posible importar una página HTML personalizada (creada por nosotros mismos) y montar un servidor local que se encargue de procesar y capturar los datos ingresados por la víctima.

Desarrollo

La práctica se llevó a cabo siguiendo una metodología estructurada, dividida en la creación del sitio y la configuración en la terminal:

  1. Desarrollo del Sitio Ficticio: Se programó una página web en HTML diseñada estratégicamente para parecer un sitio legítimo de inicio de sesión, con sus respectivos campos de usuario y contraseña.
  2. Inicialización de SET: Se ejecutó la herramienta setoolkit desde la línea de comandos con privilegios de administrador.
  3. Selección del Vector de Ataque: En el menú principal, se seleccionó la opción de ataques de ingeniería social (Social-Engineering Attacks), seguido del vector de ataque a sitios web (Website Attack Vectors).
  4. Configuración de Importación: Se optó por el método de recolección de credenciales (Credential Harvester Attack Method) utilizando la técnica de importación personalizada (Custom Import), lo que nos permitió cargar nuestra propia página en lugar de clonar una existente.
  5. Despliegue y Captura: Se configuró la dirección IP local como punto de escucha y se indicó la ruta de nuestros archivos HTML. SET levantó el servidor web alojando nuestro sitio ficticio. Al simular que una víctima ingresaba sus datos en nuestra página, la terminal interceptó y mostró el nombre de usuario y la contraseña en texto plano.

Conclusiones

Esta práctica demostró de manera contundente que, independientemente de la seguridad de la infraestructura tecnológica, el eslabón más débil en la ciberseguridad sigue siendo el usuario final. La facilidad con la que el Social-Engineer Toolkit permite integrar una plantilla HTML propia y levantar un servidor malicioso resalta el peligro de los ataques de phishing dirigidos.

Como futuro ingeniero, esta evidencia refuerza la importancia de promover una cultura de ciberseguridad. Se demostró que un diseño web atractivo y convincente no es garantía de autenticidad, por lo que es vital educar a los usuarios para verificar siempre la barra de direcciones y desconfiar de enlaces no solicitados.
