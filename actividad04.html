Actividad 04

"Una página demasiado convincente"

↓ Descargar Práctica (PDF)

Objetivos de la Práctica

  • Comprender el funcionamiento de los ataques de ingeniería social, específicamente el robo de credenciales mediante phishing.
  • Utilizar el framework Social-Engineer Toolkit (SET) para clonar una página web legítima en un entorno controlado.
  • Demostrar la vulnerabilidad del factor humano y concientizar sobre la validación de URLs y certificados digitales en los navegadores.

Introducción

La ingeniería social se basa en la manipulación psicológica para engañar a los usuarios y lograr que revelen información confidencial. Uno de los métodos más efectivos es el phishing, donde un atacante falsifica la apariencia de un sitio web de confianza para interceptar datos sensibles.

Para esta práctica se utilizó The Social-Engineer Toolkit (SET), un framework de pruebas de penetración de código abierto diseñado específicamente para automatizar ataques de ingeniería social. A través de su módulo Credential Harvester, es posible clonar rápidamente la interfaz de inicio de sesión de casi cualquier sitio web y montar un servidor local que capture los datos ingresados por la víctima.

Desarrollo

La práctica se llevó a cabo siguiendo una metodología estructurada, utilizando la terminal de comandos:

  1. Inicialización de SET: Se ejecutó la herramienta setoolkit desde la línea de comandos con privilegios de administrador.
  2. Selección del Vector de Ataque: En el menú principal, se seleccionó la opción de ataques de ingeniería social (Social-Engineering Attacks), seguido del vector de ataque a sitios web (Website Attack Vectors).
  3. Configuración del Método: Se optó por el método de recolección de credenciales (Credential Harvester Attack Method) utilizando la técnica de clonación de sitios (Site Cloner).
  4. Clonación y Despliegue: Se configuró la dirección IP local de la máquina atacante como punto de escucha. Posteriormente, se introdujo la URL del sitio web legítimo a clonar. SET descargó automáticamente el código fuente de la página y levantó un servidor web falso.
  5. Captura de Datos: Al simular el acceso de una víctima navegando hacia la IP maliciosa, la interfaz gráfica mostrada era idéntica a la original. Una vez que la víctima ingresó sus credenciales, la terminal de SET interceptó y mostró el nombre de usuario y la contraseña en texto plano.

Conclusiones

Esta práctica demostró de manera contundente que, independientemente de la seguridad de la infraestructura tecnológica, el eslabón más débil en la ciberseguridad sigue siendo el usuario final. La facilidad y rapidez con la que el Social-Engineer Toolkit permite montar un sitio fraudulento idéntico al original resalta la urgencia de implementar medidas de seguridad adicionales, como la Autenticación Multifactor (MFA).

Como futuro ingeniero, esta evidencia me permite comprender cómo operan los atacantes reales y refuerza la importancia de promover una cultura de ciberseguridad, educando a los usuarios para verificar siempre la barra de direcciones y desconfiar de enlaces no solicitados, ya que un diseño web convincente no es garantía de autenticidad.
