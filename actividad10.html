Actividad 10

"Path Traversal: Bypass con Doble Codificación URL"

↓ Descargar Reporte (PDF)

Descripción General

Explotación exitosa de Path Traversal superando mecanismos de filtrado secuencial. Se empleó la técnica de doble codificación URL (%252e%252e%252f) para ofuscar la carga útil durante la validación de seguridad, aprovechando una decodificación superflua en el servidor para lograr extraer el archivo /etc/passwd.

Objetivos de la Práctica

  • Analizar cómo las validaciones de entrada pueden ser evadidas cuando las diferentes capas de la aplicación decodifican los datos de manera inconsistente.
  • Aplicar la técnica de doble codificación URL para ocultar secuencias maliciosas frente a filtros de seguridad iniciales.
  • Comprender el comportamiento del backend al procesar decodificaciones superfluas antes de interactuar con el sistema de archivos.

Desarrollo

La evasión de este filtro se logró explotando la discrepancia entre el componente de seguridad y el servidor backend:

  1. Intercepción y Bloqueo: Se capturó la petición encargada de servir imágenes o archivos. Al intentar un ataque básico de salto de directorio (../) o una codificación URL simple (%2e%2e%2f), el servidor bloqueó la solicitud, indicando un filtrado activo.
  2. Análisis de la Arquitectura: Se planteó la hipótesis de que el sistema de seguridad (WAF) decodificaba la URL una sola vez para buscar amenazas. Sin embargo, si el servidor web interno realizaba una segunda decodificación (decodificación superflua) al enrutar la petición, se abriría una brecha.
  3. Construcción del Payload: Se codificó la secuencia maliciosa dos veces. El punto . (%2e) se convirtió en %252e, y la barra / (%2f) en %252f, ya que %25 es el valor hexadecimal del propio símbolo de porcentaje (%).
  4. Explotación: Se inyectó el payload filename=%252e%252e%252f%252e%252e%252f%252e%252e%252fetc/passwd. El filtro inicial leyó %2e%2e%2f (lo cual no reconoció como el texto plano ../) y permitió el paso.
  5. Resolución: El servidor backend tomó ese %2e%2e%2f, lo decodificó una segunda vez a ../, saltó los directorios y devolvió el contenido del archivo de contraseñas con éxito.

Conclusiones

Este laboratorio demuestra los riesgos de las arquitecturas donde múltiples componentes manejan y alteran la codificación de los datos (parsing differentials). Intentar bloquear ataques prediciendo cada forma posible de codificación es una batalla perdida.

La defensa más sólida contra el Path Traversal es normalizar completamente la ruta de entrada (resolviendo cualquier decodificación, salto de directorio o enlace simbólico) antes de validarla. Una vez normalizada, la aplicación debe verificar que la ruta final comience exactamente con el directorio base permitido antes de conceder el acceso.
